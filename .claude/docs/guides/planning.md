# Planning Guide (analyst: `plan` and `amend` modes)

## 1. Gap scan
Before you write questions, mark each category **Clear / Partial / Missing** for this request. Don't write the scan into the plan. Only Partial or Missing categories can produce questions or assumptions.

| Category | Look for |
|---|---|
| Functional scope | What's in and out, user roles, the exact behaviour of each requirement |
| Domain and data model | Entities, invariants, lifecycle and state transitions, uniqueness, ownership |
| Non-functional | Performance, limits, pagination, security, audit or logging needs, given as numbers |
| Integrations | Other modules, auth, external services, and what happens when each fails |
| Edge cases | Empty, duplicate, concurrent, deleted or archived, boundary values |
| Constraints | Existing contracts (`swagger/v1/openapi.yaml` generated by rswag, `docs/error-catalogue.md`), conventions, backward compatibility |
| Terminology | Terms the request uses differently from the code or the epics |
| Completion signals | How "done" is observed: status codes, response shape, persisted state |
| Vague words | "fast", "robust", "simple", "secure" with no number or rule attached |

## 2. Choosing questions
- Ask only when the answer would **materially change** the architecture, data model, task breakdown or tests. Ignore nice-to-haves.
- Score each candidate by **impact × uncertainty**. Keep the **top 4**, which fit one `AskUserQuestion` call.
- Every other candidate becomes a **Decision** with your recommended answer, marked `(assumed)`, for example `- Pagination default → 20 per page (assumed)`. The coordinator shows these at the approval step.
- Never ask anything already settled in `## Decisions`, in the request, or in the epics.
- If nothing is Partial or Missing, write no questions and say "No open questions". Don't invent questions to fill space.

## 3. Question format
- The question can be answered with **2–4 mutually exclusive options**, or with a short answer of 5 words or fewer.
- The first option is the recommended one.
- Each option has a `means:` line that says what choosing it does to the feature. The coordinator uses this text as the option description.

```
- Q1 Can a customer cancel within 2 hours of the start time?
  - recommended: Yes - no cut-off for the MVP
    means: Appointments::Cancel checks status only; the cut-off policy stays off by default
  - alternative: No - reject with 422
    means: adds a configurable cut-off and an EC for late cancellation
  - why: epic-5 story 1 lists the cut-off as optional, default off
```

## 4. Requirements
- Each requirement is `R<n>` with a measurable success criterion.
- Mark a requirement that is blocked by a question inline as `[NEEDS CLARIFICATION → Q<n>]`, so `amend` knows exactly what to rewrite.

## 5. Acceptance criteria and edge cases
- **Traceability.** Every R has at least one AC, and every AC or EC cites its R id, for example `AC2 (R1)`. Don't write any scenario that doesn't trace back to a requirement.
- **Integration points.** Add an AC wherever two components hand over data, for example a controller to a use case to a repository.
- **EC coverage.** Check each category below and write an EC wherever one applies. There's no minimum count.
  - Boundary values and limits (length, ranges, pagination edges)
  - Error and failure modes (not found, conflict, an invalid state transition)
  - Empty, null or missing data
  - Concurrency (double submit, a race on the same aggregate)
  - Authorization and ownership (unauthenticated, not a member, not the owner)
  - Integration failures (a dependency is unavailable or returns an error)
- Phrase Then as an observable outcome: status, body, persisted state or an emitted event. Never phrase it as an internal call.
- Use scenario-specific test data, for example `appt-ac1` or `veh-ec3`.

## 6. Amend mode
- Apply the answers. Move each answered question to `## Decisions`, and remove the `[NEEDS CLARIFICATION]` markers it resolves.
- Update the Requirements, Contracts, Tasks and ACs the answer affects, and keep them consistent with each other.
- **Don't introduce scope beyond what the answers imply.**
