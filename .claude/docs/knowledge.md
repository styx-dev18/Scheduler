## Coding

### System architecture
- A single Rails 8 API-only application (Ruby 3.4, YJIT) for the Unified Service Scheduler, backed by PostgreSQL 16 through Active Record. The app lives at the repository root.
- Layered Rails: thin controllers, one service object per use case, query objects, Active Record models as aggregates, and a pure-Ruby scheduling core in `app/domain/scheduling/`.
- The database is the final authority for correctness: GiST exclusion constraints on `(service_bay_id, time_range)`, `(technician_id, time_range)` and `(vehicle_id, time_range)` for active appointments prevent double-booking.
- The API is versioned under `/api/v1`. OpenAPI is generated by rswag from request specs; Swagger UI is at `/api-docs` when `DOCS_ENABLED=true`.

### Layers
| Layer | Folders | Owns |
|---|---|---|
| controllers | `app/controllers/api/v1/` | Params in, service call, serializer out. Envelope and `rescue_from` live in `Api::V1::BaseController`. |
| forms | `app/forms/` | `ActiveModel::Model` request objects (`BookingRequest`): structural validation only |
| services | `app/services/<namespace>/` | One use case each (`Appointments::Book`), `call` returns a dry-monads `Result` |
| queries | `app/queries/<namespace>/` | SQL range logic (`Availability::FreeBays`, `FreeTechnicians`, `DaySlots`, `Appointments::ListQuery`) |
| domain | `app/domain/scheduling/` | Pure Ruby: `TimeInterval`, `SlotTime`, `OpeningHoursPolicy`, `StatusMachine`, `AssignmentStrategies::*`. No Active Record, no `Rails.` |
| models | `app/models/` | Associations, enums, scopes, invariants. Callbacks only for simple data integrity. |
| serializers | `app/serializers/` | Alba resources; all JSON formatting |

### Implementation patterns
- Collaborators are injected as keyword arguments with defaults (`clock: Clock`, `strategy: Scheduling::AssignmentStrategies::LeastLoaded`) so specs can pass fakes.
- Expected business outcomes are `Failure(code, details)`; controllers map codes to HTTP through the error catalogue. Exceptions are for programmer errors and infrastructure faults.
- Booking runs availability check, assignment and insert in one transaction; each attempt sits in a savepoint (`transaction(requires_new: true)`) and `ActiveRecord::ExclusionViolation` triggers a bounded retry with the next candidate, then `409`.
- Domain events go through `ActiveSupport::Notifications.instrument`, published by the service after commit.
- Time: stored in UTC (`timestamptz`), half-open `[start, end)` intervals, 15-minute grid, dealership-local opening hours through IANA time zones.
- No authentication for the MVP (assumption A8); `current_customer` is a seam in `BaseController`.

### Tooling
- rbenv with `.ruby-version`, Bundler, RuboCop (`rubocop-rails-omakase`), Brakeman, bundler-audit, Bullet, Lefthook.
- Local development uses the Homebrew PostgreSQL 16 server. Docker Compose files exist for later verification once a container runtime is chosen.
- The gate `.claude/scripts/verify.sh` runs `bin/rails zeitwerk:check`, `bundle exec rubocop`, `bin/brakeman` and `bundle exec rspec` when they exist; `--quick` runs `zeitwerk:check` only.

## Testing

### Test architecture
- RSpec with FactoryBot, Faker, shoulda-matchers, rswag and SimpleCov.
- `spec/domain` loads only `spec_helper` and runs without Rails or a database. Everything else loads `rails_helper` and uses real PostgreSQL.
- Layout mirrors `app/`: `spec/domain`, `spec/models`, `spec/forms`, `spec/services`, `spec/queries`, `spec/requests`, `spec/concurrency`, `spec/support`.

### Test data and mocking
- Each scenario uses unique, namespaced test data, for example `appt-ac1`. Specs share no mutable state.
- Substitute injected collaborators in service specs. Never mock PostgreSQL behaviour such as exclusion constraints or range overlap.
